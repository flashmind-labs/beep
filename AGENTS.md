# Agent notes

Check the implementation when changing a feature; these notes may lag behind it.

## Project

Desktops, phones and `beep-node`s talk directly over a signed mesh. A phone
pairs over iroh with a desktop's one-use ticket (valid five minutes) and then
reaches nodes without a running desktop. Desktop and node membership persists.
Phones use the desktop controller role for shared projects, groups, pins,
credentials and settings. Agent and forge credentials may be shared with nodes.

`beep-server` only receives problem reports. The apps have no assistant and no
server features, and nodes do not connect to it.

## Code map

- `crates/mesh`: signed membership, tickets and replicated state.
- `crates/fleet`: desktop-side projects, credentials, settings and mesh operations.
- `crates/node`: agents and their MCP tools, files and sync, mesh, machines and processes.
- `crates/proto`: node and mesh messages, their data types and the lenient reader.
- `crates/server`: the problem report receiver.
- `apps/desktop/src`: UI grouped by feature; `*-state.ts` holds tested logic.
- `apps/desktop/src-tauri/src`: desktop commands and mesh integration.
- `apps/desktop/src-tauri/gen`: the iOS and Android projects, generated by
  `scripts/tauri-init.sh` and never committed.

## Workflow

- Every feature the user asks for gets a GitHub issue in `flashmind-labs/beep`
  (`gh issue create`) before work starts. Link it from the commit or close it
  when the feature ships. A subagent on a small model writes the issue's
  title and body from your notes: Haiku 5.5 (`claude-haiku-5-5`) under Claude
  ACP, Terra 6.1 (`gpt-6-1-terra`) under Codex ACP.
- Label every issue: one or more areas (`area: desktop`, `area: phone`,
  `area: node`, `area: mesh`, `area: sync`, `area: server`, `area: agents`
  for coding agent sessions, ACP and MCP, `area: release` for builds,
  signing and CI, `area: assistant` for the removed server assistant,
  `command-center`, `plugin`), exactly one type (`bug`, `enhancement`,
  `performance`, `refactor`, `security`, `discussion`, `documentation`), and
  `priority: low` when it fits.
- Close an issue as completed only when main implements all of it and a
  commit or `file:line` shows it. Partial work stays open.
- One Cargo workspace holds every crate and the desktop app; versions live
  in the root `[workspace.dependencies]`. The desktop (`beep-desktop`) is
  outside `default-members`: `just run`, `just desktop-check`,
  `just desktop-build`.
- The phone app is `apps/desktop` built for iOS and Android: `just ios-run`
  (connected iPhone), `just ios-sim-run`, `just android-run`. On a phone it is
  a mesh observer (`cfg(mobile)`): no node, no agents, no terminals hosted.
- Debug with the Beep MCP `beep_status` and `beep_logs` tools; `beep_report` asks
  the user before sending. Reports hold private logs: an issue carries only
  the report reference. `just reports`, `just report <reference>` and
  `just report-solved <reference>` manage stored reports.

## Code

- Less code is better. Before writing a component, helper or style, look for
  the one that exists and use it. When two places need the same thing, move
  it to the shared module instead of copying it. Delete what a change makes
  unused, in the same change.
- Use established libraries for parsing and shared behavior, not handwritten
  parsers or utilities.
- Keep related types, constants and functions together in existing modules.
  No file for a single declaration and no wrapper that only forwards.
- Put the main flow before its supporting details, so a file reads top to
  bottom. Separate a function's stages with blank lines, including around
  control-flow blocks and before a tail return.

### TypeScript and React

- The UI is React with TypeScript. A piece of UI is a React component by
  default: state in hooks or a store, events as props, lists as keyed
  elements. Do not build or patch DOM by hand (`createElement` chains,
  `innerHTML`, `querySelector` wiring, manual listeners); when you touch code
  that does, move it to a component. The exception is something very simple
  that has no state and no events, such as a formatter or a constant.
- Model the domain in types: named types and discriminated unions for
  identifiers, navigation, requests and state, with exhaustive handling, not
  loose strings and bags of optional fields.
- No `undefined` in models and APIs: use `null` or a named variant, and make
  required values required. Handle missing values from browser and library
  APIs at the boundary.
- No `any`, non-null assertions or casts that bypass checking. Validate
  external data before using it.
- Use typed libraries for navigation, popovers, shortcuts and other shared
  behavior (`react-aria-components` is already here). State has one owner.

### Rust

- Small modules grouped by responsibility, following `crates/node` and
  `crates/server`. `mod.rs` holds declarations, re-exports and a thin public
  API. Preserve public paths and wire formats when moving code.
- Unit tests live in the crate's `src/tests/`, grouped by module and declared
  at the end of the module with `#[cfg(test)]` and `#[path]`. Public API
  tests go in the crate's `tests/`.
- Domain types for identifiers, meaningful names and paths; `String` only for
  text. Enums for fixed protocol and state sets, deriving `PartialEq` and
  `Eq`, matched directly. Convert strings at external boundaries and keep
  unknown wire values in a fallback variant when needed.
- Conversions go through `From`, `TryFrom`, `FromStr`, `AsRef` and `Display`,
  not methods such as `from_acp` or `as_str`. Use Strum derives
  (`EnumString`, `AsRefStr`, `IntoStaticStr`, `Display`, with
  `#[strum(serialize = "...")]` where names differ) when they keep the exact
  accepted values, labels and errors. Validation lives in the conversion
  traits; serde and wire representations stay independent of them. Write
  `Into::<Target>::into(value)` rather than an inferred `value.into()`.

## UI

Change the app's UI directly; there are no mockups. Never commit or push
screenshots: the PNGs of `apps/desktop/tests/browser/ui-baseline.spec.ts` are
gitignored and each machine records its own on the first run. The text
snapshots next to them stay committed: update them with the change and add a
test for a screen that has none. Check the result in the real app too: WebKit
lays some things out differently from the test browser.

### The desktop's style

A dark, Linear-style app with monospaced chrome, frosted glass on the layers
that float, and brush-stroke paintings for atmosphere. The phone takes the
same look, sized for touch, in `mobile.css`.

- **Type.** Chrome (labels, tabs, buttons, statuses, numbers, details) is in
  the mono face at 11 to 12px. Titles and reading text stay in the sans.
  Section labels are small mono capitals.
- **Shape.** Nearly square corners. Spacing separates things, not borders: a
  row has no hairline, a card has no outline. One accent, used rarely: the
  primary action, the current item, a running state.
- **Cards and rows.** A card is a faint fill with the lit top edge
  (`var(--lit)`). A list is plain rows that fill on hover. A row's secondary
  actions stay hidden until the row is pointed at or focused. One line per
  item where it fits; details in mono under the name, not in boxes.
- **Glass.** Only on floating layers (palette, menus, dialogs, composers,
  cards over a painting), never on reading areas. A blur on an element
  becomes what its fixed descendants are placed against, so put it on a
  `::before` layer behind.
- **Paintings.** `src/ui/painted-art.tsx` paints scenes in blocks of short
  strokes: a sunrise for the first run, the day's painting on the start screen
  and empty pages (`DailyArt`, `PaintedEmpty`: the sunrise, haystacks, the
  lily pond and Parliament take a day each, with the subject in the upper
  half, clear of the headline), the dawn haze down the sidebar and as a faint band along
  the top of Home and Projects, gone before the first cards, and a wanderer
  above a sea of fog beside the lanes of a project board in a wide window. A
  scene paints itself once after the app opens; from then on its pixels sway
  and flicker gently while it is on screen. The haze stays still, and with
  Reduce motion every scene is drawn finished and still. Words sit on a
  glass card or a clear patch, not on the strokes. A painting belongs on an
  empty screen, above the content or in the room beside it, never behind cards
  or reading text.
- **Motion.** A spinner turns for work in progress and pauses when the window
  is hidden. Short transitions on navigation. A finished painting moves
  while it is on screen and rests when hidden. Nothing else moves, and nothing
  takes over the user's desktop.
- **Empty and loading.** Say what to do next and offer the one action. No
  placeholder rows such as "None running": leave the section out.

### Where things go

- Components: `src/ui/kit.tsx` (`Button`, `CopyButton`, `Chip`, `ChipToggle`,
  `Checkbox`, `Switch`, `Spinner`, `Section`, `SectionHead`, `LineRow`,
  `EmptyPanel`, `SkeletonRows`, `onRowKey`), icons in `src/ui/icons.tsx`,
  words and numbers in `src/ui/format.ts`. Use them; a raw `<button>` or a
  second spinner is a bug. A new control used in two places goes into the
  kit.
- Style values: the custom properties, not literals. `--ctl-h` sets control
  height for everything inside a container; `--ctl-fill` and `--ctl-fill-hi`
  are the control fills; `--lit` is the lit edge; `--mono` and `--body` are
  the faces; `--ink`, `--fg`, `--muted`, `--dim` and `--accent` are the
  colours; `--radius` and `--radius-sm` are the corners; `--glass` and
  `--glass-solid` are the frost and fill of floating layers; `--paintings`
  shows or hides the paintings. A skin (`dist/skins.css`) sets them, so it
  changes them all at once.
- Stylesheets in `apps/desktop/dist`: structure that the phone shares goes in
  `style.css`, `center.css` or `sheets.css`, unscoped. The desktop's look goes
  in `native.css` under `body:not(.mobile)`; the phone's in `mobile.css`.
  Extend the rule that exists instead of appending one that overrides it, and
  group selectors that share a look.
- The phone uses the same markup. New markup needs a sensible unscoped
  default, and a desktop-only element starts hidden.

## Changelog

Record every user-visible change before finishing, as a new file per change in
`changelogs/unreleased/<app>/` (`desktop`, `node`, `android`, `ios` or
`server`), named after the issue or branch, such as `579-ghostty-terminals.md`.
A subagent on a small model writes it: Haiku 5.5 (`claude-haiku-5-5`) under
Claude ACP, Terra 6.1 (`gpt-6-1-terra`) under Codex ACP. Never edit another
change's file or the `changelogs/<app>.md` files. Record a shared change in
each affected app. A file holds `### Added`, `### Changed`, `### Fixed`,
`### Security` or `### Performance` sections of `- ` items, written from the
user's view and naming the platform. Skip internal churn. Never invent past
release notes or edit published entries. Check with
`python3 scripts/changelog.py check`.

```markdown
### Fixed

- Desktop: a terminal stream that lost a message attaches again instead of
  stopping.
```

## Releases and deployment

- Apps stay on 0.x until production: minor or patch bumps only. Do not run a
  release recipe, tag or upload a build without cutting a new version for
  that app. Release recipes commit and tag, and `just release` also pushes:
  read the recipe, the `justfile` and the `.forgejo/workflows/` file first.
- A release freezes the app's changelog
  (`python3 scripts/changelog.py freeze <version> --path changelogs/<app>.md`),
  which collects its files into a dated entry and deletes them. Release pages
  and desktop updater feeds use those notes. Never publish without them.
- Desktop and node tags trigger signed builds and release uploads. The phone
  app is the desktop Tauri app: `android-v*` and `ios-v*` tags build it and
  upload to Play and TestFlight, with each phone version in
  `tauri.android.conf.json` or `tauri.ios.conf.json`. Android releases stay
  off production while apps are on 0.x.
- Production is deployed from the private ops repo. Ask before deploying the
  server, and before stopping or recreating it. The on-prem bundle is retired.

## Wire compatibility

Released phones, desktops and nodes must keep working together over the mesh.

- Node and mesh messages are positional msgpack. Append fields with
  `#[serde(default)]`; never insert, reorder, retype or remove fields, or use
  `skip_serializing_if` or `to_vec_named`. Read with
  `beep_proto::lenient::from_slice`.
- Signed mesh types (`Device`, `OpBody`, `Signed`) cannot gain fields in
  place: change `SIGN_DOMAIN`, the mesh ALPNs and `MESH_DIR` together.
- Terminal host `Request`, `Reply` and `Hello`, and transfer `Manifest`,
  cannot gain fields while released readers using plain `rmp_serde` remain
  reachable. Change a protocol's bytes only with a protocol name bump.
- Current mesh ALPNs: `beep-peer/2` and `beep-join/2`. Sync uses
  `beep-sync/7`.

## Mesh operations

- A desktop creates one-use pairing tickets. Nodes join the mesh and never
  mint tickets. A temporary machine is removed after 24 hours offline; other
  machines are not removed automatically.
- A new Git project copies the committed checkout and Git metadata once.
  After that, repositories exchange commits through Git. Uncommitted edits
  stay local until an explicit handoff to a clean checkout at the same
  commit. Non-Git folders keep file sync. Linked worktrees and submodules
  stay on their machine.
- Syncthing project exclusions apply on every imported machine, including
  when offline machines reconnect; the shared folder is never paused.
